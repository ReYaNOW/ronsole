# Паритет терминала: общий крейт `ronsole-term`, протоколы и стили (Ronsole → RRiter)

Дата: 2026-10-21. Статус: утверждена пользователем 2026-10-21 (ревью: консультант — 2 круга, ds-high — APPROVE в раунде 4).
Справочник форматов (байты, источники): `docs/superpowers/specs/2026-10-21-terminal-protocol-ref.md` — далее «справочник». Исходный запрос: сравнение Ronsole с Alacritty (`~/Рабочий стол/term_parity.md`) — закрыть то, чего не хватает и что реально стоит добавить, затем то же для терминала RRiter.

## 1. Цель

1. Ronsole получает недостающую протокольную поверхность и стили текста, которыми пользуются реальные TUI (Neovim, Claude Code, Codex, fzf, lazygit, ssh).
2. Терминал RRiter получает то же самое не копией, а через общий крейт `ronsole-term`, вынесенный из ядра Ronsole: сетка, VT-парсер, SGR, протоколы и кодировщики ввода пишутся и тестируются один раз.
3. Shift+Enter вставляет перевод строки в Claude Code в обоих терминалах.

Критерий успеха — раздел 10 (приёмка).

## 4. Архитектура: крейт `ronsole-term`

### 4.1 Расположение и сборка

* Каталог `crates/ronsole-term/` в репозитории Ronsole; корень Ronsole становится workspace (`members = [".", "crates/ronsole-term"]`). Бинарь Ronsole зависит от крейта по `path`.
* Зависимости крейта: `vte` (та же версия, что у Ronsole сейчас, 0.15, `std`), `unicode-width`. Крейт реэкспортирует `vte`, чтобы потребитель не держал второй версии.
* Крейт платформенно-нейтрален: никакого `std::os::*`, `libc`, `/proc`, env, потоков, каналов и I/O. Допустимы тип `std::time::Instant` и `Arc`; `Instant::now()` крейт не вызывает — время передаёт хост аргументом `now` (тесты детерминированы).
* RRiter подключает `ronsole-term = { git = "https://github.com/ReYaNOW/ronsole", rev = "<sha>" }`. Требование: крейт собирается тем же тулчейном и командами, что и RRiter сейчас, на Linux, и проходит `cargo check` под Windows- и macOS-таргетами. Работоспособность git-зависимости при корневом манифесте Ronsole (`cargo-features = ["panic-immediate-abort"]` — тот же, что у RRiter; профили зависимостей потребитель игнорирует) проверяется реальным потребителем в конце этапа 1 (решение 23), а не предположением; что менять в манифестах — по фактической ошибке этой проверки.
* `make test` и `make codex_test` Ronsole прогоняют и тесты крейта (`--workspace` или отдельный вызов для крейта, `Makefile:80-95`); lint изменённых файлов и генератор карты (`gen_project_map.py`) охватывают `crates/`.

### 4.3 Выход событий из сетки (решение 17)

Сетка не держит каналов и чужих типов и ничего не копит. Всё, что уходит наружу, она синхронно отдаёт приёмнику, который хост передаёт в каждый вызов:

```text
trait TermSink {
    fn reply(&mut self, bytes: &[u8]);              // ответ в PTY (DA, CPR, DECRQM, OSC-цвета, kitty ?u, XTVERSION)
    fn title(&mut self, title: &str);               // OSC 0/2
    fn clipboard_set(&mut self, text: String);      // OSC 52, декодированный UTF-8 (5.7)
    fn working_directory(&mut self, host: &str, path: &[u8]); // OSC 7, percent-decoded байты (5.8)
}
```

* Каждый вход байтов в сетку принимает приёмник: батч PTY, `finish_terminal_output_stream`, `write_terminal_spawn_error`, сброс срока 2026 (5.4). Других путей записи текста в сетку нет.
* Приёмник вызывается под блокировкой сетки в том потоке, который вызвал метод сетки: батч PTY — поток разбора, `flush_expired` (5.4) — главный поток. `title` — кеш заголовка хоста, порядок блокировок прежний (сетка, затем кеш).
* С этапа 2 ответы одного вызова (`advance` или `flush_expired`) крейт собирает в свой переиспользуемый буфер и отдаёт одним `reply` в конце вызова; буфер ограничен 64 KiB, ответы сверх предела отбрасываются. `reply` хоста — `try_send` копии в канал писателя PTY `sync_channel(32)`, который дренирует его параллельно (Ronsole — нынешний канал; RRiter переходит с неограниченного `channel()`). Так сброс буфера 2026 с десятками запросов — одно сообщение, а не переполнение канала; потеря возможна, только если писатель не забрал 32 батча подряд (заблокированный PTY), как сейчас в Ronsole.
* `clipboard_set` и `working_directory` хост передаёт в главный поток своим механизмом с заменой: на сессию хранится не больше одного ожидающего значения каждого вида, новое заменяет старое. Память выхода сетки ограничена: ≤ 32 × 64 KiB ответов в канале, ≤ 4 MiB буфера обмена и один путь ≤ 4096 байт (5.8) на сессию. Вход не ограничен: vte с `std` копит OSC в неограниченном `Vec` (`vte-0.15.0/src/lib.rs:64`, `:544-551`), поэтому предел `Pd` (5.7) проверяется после накопления — как сейчас, вне рамок (11).
* Без событий крейт ничего не аллоцирует; буфер ответов переиспользуется через `clear()`.

### 4.4 Конфигурация сетки хостом

* `TermIdentity { name: &'static str, version: &'static str }` при создании — для XTVERSION и DA2 (Ronsole: `ronsole` + версия пакета; RRiter: `rriter` + своя).
* `TermPalette { foreground, background, cursor, ansi: [Rgb; 16] }` — задаётся при создании и при смене темы или настройки. Это та же палитра, которой рисует рендер хоста: ответы OSC 10/11/12/4 и цвета по умолчанию на экране совпадают. Ronsole: `background` — настройка `terminal_background` (`config.rs:71`), остальное — нынешние константы рендера и `ANSI_16_COLORS`; смена настройки обновляет палитру всех сессий. RRiter: из темы. Цвета 16–255 вычисляются как сейчас (куб 6×6×6 и градации серого).
* Лимит строк скроллбэка — параметр создания (RRiter 10000, Ronsole — нынешнее значение).

### 4.5 Ячейка

* `flags: u8` → `u16` (помещается в нынешнее выравнивание; `size_of::<Cell>() <= 24` остаётся тестом).
* Биты: WIDE, WIDE_SPACER, INVERSE, DIM, CONCEAL, HOST_HIDDEN, BOLD, ITALIC, STRIKE и поле стиля подчёркивания из 3 бит: 0 нет, 1 одинарное, 2 двойное, 3 волнистое, 4 точечное, 5 штриховое. Бит UNDERLINE заменяется полем; сигнатура `set_sgr_style(inverse, underline, dim)` меняется вместе с вызовами (`terminal.rs:987`, `:993`, тесты `renderer/terminal_ui.rs:3026-3077`).
* `CellExtra` получает `underline_color: Option<TerminalColor>` и `hyperlink: Option<Arc<Hyperlink>>`, `Hyperlink { id: Option<Box<str>>, uri: Box<str> }`. Клетки, напечатанные при одной активной ссылке и одном цвете подчёркивания, разделяют одну аллокацию `Arc<CellExtra>`; клетка с zero-width символами получает свою копию при записи. Печать обычного текста без ссылки и цвета подчёркивания не аллоцирует.
* CONCEAL (решение 19) копируется из пера при записи клетки (SGR 8 вкл, 28 и 0 выкл). HOST_HIDDEN — нынешний HIDDEN: ставит только хост через метод сетки, любая запись в клетку его снимает; пер его не несёт, поэтому очистка dev-баннера не трогает CONCEAL. Рендер не рисует глиф и оформление при любом из двух битов. Выделение и копирование берут символы CONCEAL-клеток как есть.
* BOLD хранится в клетке для выбора начертания; нынешнее осветление индексов 0–7 → 8–15 при жирном сохраняется.

### 4.6 Публичный API крейта

Сейчас всё `pub(crate)` (раздел 3). Крейт открывает только:
* сетку `Term`: создание (размер, лимит скроллбэка, `TermIdentity`, `TermPalette`), `advance(bytes, now, sink)`, срок 2026 (5.4), resize с reflow, скролл и выделение, чтение строк и клеток видимой области и скроллбэка, запрос ссылки в клетке (5.5), смена палитры, скрытие клеток хостом (HOST_HIDDEN), чтение режимов (DECCKM, отслеживание мыши и его кодирование, фокус 1004, bracketed paste 2004, флаги Kitty, альтернативный экран, видимость курсора), признаки готовности (нынешний `presentation_ready`);
* `Cell` с полями только для чтения через методы (символ, цвета, флаги, стиль и цвет подчёркивания, ссылка, zero-width) и конструктор пустой клетки; запись клеток — только методами `Term`;
* `TerminalColor`, `Rgb`, разрешение цвета через `TermPalette` (с учётом inverse/dim/bold), `terminal_force_text_presentation`;
* кодировщики ввода (клавиши 5.3, мышь, bracketed paste, фокус), поиск URL (5.6), `TermSink`, `TermIdentity`, `TermPalette`, реэкспорт `vte`.

Точные имена — план; всё остальное в крейте приватно.

## 5. Поведение крейта

Все форматы байтов — по справочнику; ниже решения сверх него.

### 5.1 SGR

| Код | Действие |
|---|---|
| 1 / 22 | BOLD вкл / BOLD и DIM выкл |
| 2 | DIM |
| 3 / 23 | ITALIC вкл / выкл |
| 4, 4:1 / 4:0, 24 | одинарное подчёркивание / выкл |
| 4:2, 21 | двойное (21 — как в xterm/kitty, не «bold off») |
| 4:3 / 4:4 / 4:5 | волнистое / точечное / штриховое |
| 7 / 27 | INVERSE (как сейчас) |
| 8 / 28 | CONCEAL вкл / выкл |
| 9 / 29 | STRIKE вкл / выкл |
| 58;5;n, 58:5:n, 58;2;r;g;b, 58:2::r:g:b, 58:2:r:g:b / 59 | цвет подчёркивания / сброс |
| 0 | сброс всего, включая цвет подчёркивания и стиль |

Подпараметры через двоеточие разбираются в пределах одного параметра; `4:x` с неизвестным `x` — одинарное. 5/6 (мигание), 53/55 (надчёркивание) и прочие неизвестные коды игнорируются, как сейчас. Truecolor 38/48 остаётся как в Ronsole.

### 5.2 Запросы и исправления

* `CSI c` / `CSI 0 c` → DA1 как сейчас; `CSI > c` / `CSI > 0 c` → DA2 `CSI > 1 ; <версия> ; 0 c`, где версия = major·10000 + minor·100 + patch из `TermIdentity`. `CSI = c` (DA3) не отвечается.
* `CSI > q` / `CSI > 0 q` → XTVERSION `DCS > | <name>(<version>) ST`.
* DECRQM `CSI ? Ps $ p` → `CSI ? Ps ; Pm $ y`: `Pm` 1/2 для всех реализованных приватных режимов (1, 6, 7, 25, 47, 1047, 1049, 1000, 1002, 1003, 1004, 1006, 2004, 2026), 0 для остальных. ANSI-форма `CSI Ps $ p` → `CSI Ps ; Pm $ y`: 1/2 для режима 4 (IRM, уже реализован — `insert_mode`, `terminal.rs:3915-3917`), 0 для остальных.
* `CSI u` без intermediates и параметров — DECRC, как сейчас; с `?`, `>`, `<`, `=` — Kitty (5.3), курсор не трогается.
* OSC 10/11/12 с `?` → `OSC N ; rgb:rrrr/gggg/bbbb` из `TermPalette` (16 бит на канал, байт повторён: `0xab` → `abab`); терминатор ответа повторяет терминатор запроса (BEL или ST). OSC 4 `; idx ; ?` (несколько пар в одной последовательности) → по ответу на индекс 0–255. Установка цветов OSC 4/10/11/12 и сбросы 104/110/111/112 — no-op (изменяемой палитры нет, как сейчас).

### 5.3 Kitty keyboard protocol

* Поддерживаемые флаги: 1 (disambiguate), 2 (типы событий), 8 (все клавиши как escape), 16 (associated text). Флаг 4 (alternate keys) не поддерживается: запрошенные неподдерживаемые биты маскируются, ответ на `CSI ? u` — `CSI ? <текущие флаги> u` после маски.
* Push `CSI > f u`, pop `CSI < n u`, set `CSI = f ; mode u` — по справочнику. Отдельные стеки для основного и альтернативного экрана, глубина до 32 (переполнение выбрасывает самую старую запись). RIS (`ESC c`) и DECSTR сбрасывают оба стека и флаги в 0.
* Событие не зависит от оконной системы: `KeyEvent { physical: u64, key: TermKey, base: Option<char>, mods: { shift, ctrl, alt, super }, kind: Press | Repeat | Release, text: Option<&str> }`.
  * `physical` — непрозрачный идентификатор физической клавиши от хоста, одинаковый у press, repeat и release одной клавиши. Ronsole — keycode Wayland (его надо прокинуть в `KeyInput`, сейчас он есть только в `queue_key_event`, `runtime.rs:1672`). RRiter — своя таблица `KeyCode` → число и для `PhysicalKey::Unidentified(NativeKeyCode)` тег варианта в старших 32 битах и код в младших (`Xkb(u32)` и `Android(u32)` занимают весь u32, поэтому тип u64); форма таблицы — план.
  * `TermKey` — именованные клавиши (Enter, Tab, Backspace, Escape, стрелки, Home/End, PageUp/Down, Insert/Delete, F1–F12, клавиши keypad, клавиши-модификаторы Left/Right Shift, Ctrl, Alt, Super, CapsLock, NumLock, ISO Level3 Shift — коды из таблицы functional keys протокола Kitty, которых в справочнике нет: план вносит их туда с цитатой источника до тестов) и `Char(char)` — несмещённый символ клавиши в текущей раскладке (в русской `ф`, не `a`; со Shift всё равно `ф`, не `Ф`).
  * `base` — несмещённый символ той же физической клавиши в раскладке US для всего буквенно-цифрового блока, включая знаки (`a` для A, `/` для Slash, `[` для BracketLeft), `None` для остальных клавиш.
  * `text` — текст, который клавиша даёт с текущими модификаторами (для флага 16 и для пути текста).
  * `mods` не содержат модификаторов, потраченных на получение текста: AltGr/ISO Level3 (на Windows — Ctrl+Alt, давшие текст) снимаются хостом, клавиша идёт как текст (правило RRiter `AGENTS.md` §5 о Windows AltGr).
* Кодировщик — метод сетки: `encode_key(&KeyEvent, out: &mut Vec<u8>) -> KeyOutcome`, режимы (DECCKM, флаги Kitty) берёт из сетки. `KeyOutcome`: `Sent` (байты в `out`, хост пишет их в PTY и не отправляет `text` этой клавиши), `Text` (хост отправляет `text` путём текста, как сейчас), `Ignore` (ничего не отправлять: release без флага 2; клавиша-модификатор без флага 8; release Enter, Tab, Backspace без флага 8 — справочник, пример «Enter release»; release без отправленного press).
* Флаги 0 — байты те же, что сейчас в Ronsole (`input.rs:1150-1161`, `:1199-1226`, `:1235-1239`), плюс решение 13 (Shift+Enter → `ESC CR`): Ctrl+клавиша кодируется по физической клавише через `base` (Ctrl+С в русской раскладке → `0x03`, Ctrl+/ → `0x1f`, Ctrl+[ → `ESC`); Alt+символ — `ESC` + текст текущей раскладки (Alt+ф → `ESC ф`).
* Флаги ≥ 1, код клавиши в CSI u (решение 18): `base`, если зажат Ctrl, Alt или Super и `Char` не ASCII; иначе `Char`. Ctrl+С в русской раскладке → `CSI 99;5u`.
* Исход repeat вычисляется как для press, по текущим модификаторам (`Text` или `Sent`; тип события 2 в байтах — только при флаге 2). Набор ниже ведётся только при флаге 2: repeat с исходом `Sent` — код из набора, если клавиша там есть, иначе пара добавляется; repeat с исходом `Text` удаляет пару клавиши (её release будет `Ignore`). Без флага 2 результат прежний: автоповтор букв идёт путём текста.
* Release (флаг 2) отправляется только для клавиши, чей press ушёл в PTY как `Sent`, и с кодом клавиши этого press, а не вычисленным заново (отпущенный раньше буквы Ctrl не меняет код release). Сетка хранит пары «`physical` → отправленный код» в массиве фиксированной длины 16, без аллокаций; release клавиши вне набора — `Ignore`; полный набор вытесняет самую старую пару. Так не утекают release клавиш, которые перехватил хост (вставка, копирование, глобальные сочетания). Набор очищается при потере фокуса, смене флагов и RIS.
* Все нажатия, которые уходят в PTY, идут через `encode_key`; прямых записей байтов клавиш в обход него нет (Ronsole Ctrl+C `input.rs:462-464`, RRiter Ctrl+C `keyboard.rs:589` переходят на кодировщик; legacy-результат прежний, `0x03`). Сочетания, которые перехватывает хост, в кодировщик не попадают.
* Текст IME (коммит композиции) — всегда UTF-8 путём текста, при любых флагах, как в Kitty; клавиши, поглощённые IME во время композиции, в кодировщик не идут (RRiter `keyboard.rs:533` переходит на путь текста).
* Ожидаемые байты тестов — таблица примеров справочника (исправленная 2026-10-21).
* Хосты перестают отбрасывать Release в терминал (Ronsole `input.rs:427`) и передают Repeat отдельным видом события; без флага 2 результат прежний.

### 5.4 Синхронный вывод (режим 2026)

Решение 16: буферизация байтов, сетка во время обновления не меняется.

* `CSI ? 2026 h` включает режим со сроком `now + 150 мс` от первого `h`; повторный `h` при активном режиме срок не продлевает. Байты после `h` не применяются к сетке, а копятся в буфере сетки.
* Крейт ищет в копящихся байтах `CSI ? 2026 l` (с учётом разреза последовательности между батчами). Найден — буфер применяется к сетке целиком одним проходом, режим снят, разбор продолжается обычным образом.
* Буфер достиг 2 MiB или наступил срок — то же применение и снятие режима. Срок проверяет метод `flush_expired(now, sink)`; `sync_deadline()` отдаёт срок сессии. Хост обязан вызвать `flush_expired` не позже срока, даже если байтов больше нет, для каждой сессии, в том числе фоновой вкладки (её ответы ждут в буфере): Ronsole — из главного цикла, где таймаут ожидания событий не больше минимального срока по всем сессиям (нынешний `loop_control` берёт сроки только активной вкладки, `app.rs:1312-1321`, — расширяется); RRiter — из своего цикла событий так же (`ControlFlow::WaitUntil`). Вызов идёт в главном потоке под блокировкой сетки с приёмником сессии (4.3).
* `advance` и `flush_expired` возвращают одинаковый итог: изменилась ли сетка и появился ли новый срок 2026. Изменилась — хост увеличивает `content_generation`, ставит `dirty` и будит главный поток (от generation зависят поиск и скан dev-баннера). Появился срок без изменения сетки (батч из одного `h`) — хост будит главный поток только чтобы тот пересчитал таймаут ожидания; кадра это не вызывает. Пока режим активен, батчи кадров не вызывают. Кадр по любой другой причине (анимация, `show_fps`, ввод, resize, другая вкладка) рисует сетку как есть — последнее завершённое состояние. `withhold_active_frame` в Ronsole не меняется и в 2026 не участвует.
* Ответы на запросы внутри буфера уходят при его применении. Ёмкость буфера между обновлениями сохраняется до 64 KiB, больше — освобождается; без режима 2026 буфер не выделяется.
* DECRQM `CSI ? 2026 $ p` → 2, пока режим не активен; внутри буфера запрос отвечается при применении буфера, когда режим уже снят, то есть тоже 2.

### 5.5 OSC 8

* `OSC 8 ; params ; URI ST` (и BEL) начинает ссылку, `OSC 8 ; ; ST` завершает. Параметр `id=` сохраняется. URI длиннее 2083 байт или с управляющими символами — последовательность игнорируется (текущая ссылка закрывается).
* Клетки, напечатанные при активной ссылке, хранят `Arc<Hyperlink>` (4.5). Ссылка переживает скроллбэк и reflow вместе с клеткой.
* Крейт даёт хосту запрос «ссылка в клетке (row, col)» и «диапазон клеток той же ссылки в видимых строках». Одна ссылка — та же `Arc`, либо равные `uri` и непустой `id` (справочник §4); ссылки без `id` с равным URI, напечатанные отдельными OSC 8, — разные.

### 5.6 Обычные URL

* Чистая функция крейта ищет URL вокруг колонки в логической строке (перенесённые строки склеиваются): схемы `http://`, `https://`, `file://`; символы до пробела или управляющего; с конца отрезаются `.,;:!?'"` и непарные `)]}>`. Широкие символы учитываются по колонкам.
* Вызывается только по событию (движение мыши с зажатым Ctrl, Ctrl+клик), не каждый кадр. OSC 8 в клетке имеет приоритет над найденным URL.

### 5.7 OSC 52

* Только запись: `OSC 52 ; Pc ; Pd`, где `Pc` пуст или содержит `c` или `s` → `TermSink::clipboard_set`. `Pc` только из `p` или цифр — игнорируется (primary selection нет).
* `Pd` — base64; декодированный размер до 4 MiB (длина `Pd` больше `4·⌈4 MiB / 3⌉` — игнорируется без декодирования); невалидный base64 или не-UTF-8 — игнорируется. `Pd` = `?` (чтение) — без ответа. Пустой `Pd` — игнорируется.
* Хост выполняет запись в своём главном потоке по событию (Ronsole: `TerminalInteraction::set_clipboard_text`; RRiter: `App::set_clipboard_text`).

### 5.8 OSC 7

* `OSC 7 ; file://host/path` → `TermSink::working_directory(host, path)`: `host` — строка, `path` — percent-decoded байты, начинаются с `/`. Игнорируются: не-`file` схема, путь не с `/`, путь длиннее 4096 байт после декодирования, невалидный percent-encoding, байт NUL после декодирования, `host` не UTF-8. Крейт не строит `PathBuf` и не знает платформы.
* Хост принимает событие, только если `host` пуст, `localhost` или совпадает с именем локальной машины, и хранит последнее значение на сессию. Преобразование в путь — у хоста: на Unix байты как есть (`OsStr::from_bytes`); в RRiter на Windows — только UTF-8, форма `/C:/x` → `C:\x`, иначе событие игнорируется (UNC отсекается проверкой `host`). RRiter — через `src/platform` (RRiter `AGENTS.md` §5 Platform invariants). Использование — Q12 (раздел 12) для Ronsole, решение 21 для RRiter.

## 6. Ronsole: рендер, шрифты, ввод

### 6.1 Начертания

* Встраиваются `JetBrainsMonoNerdFont-Bold.ttf`, `-Italic.ttf`, `-BoldItalic.ttf` той же версии Nerd Fonts, что и нынешний Regular, в `src/fonts/` (правило Ronsole `AGENTS.md:306`: шрифты меняются в задаче про шрифты). Файлы берутся из официального релиза `ryanoasis/nerd-fonts`; лицензия OFL — рядом.
* Ключ кеша глифов `(c, presentation)` → `(c, presentation, face)`, `face` — 2 бита. Начертание разбирается лениво при первом глифе этого начертания (байты в `.rodata`, без копии в heap).
* Нет глифа в нужном начертании — тот же символ из Regular-цепочки (встроенный Regular первым, затем системный моно, символьные и emoji — решение 24). Синтетического наклона и утолщения нет.
* Атлас, его размер и сброс при заполнении не меняются.

### 6.2 Оформление

* Новый слой тела терминала после Glyph: подчёркивание всех стилей и зачёркивание. Цвет — цвет подчёркивания клетки, иначе цвет текста (после inverse/dim).
* Толщина линии `max(1, round(scale))` px, Y линий — от округлённого baseline, без накопления дробных шагов (правило пиксельной стабильности Ronsole). Двойное — две линии с зазором в толщину; волнистое — новый режим шейдера (SDF-волна внутри прямоугольника высотой ~3 толщины, период по ширине клетки, фаза от колонки, чтобы волна была непрерывной между клетками); точечное и штриховое — тот же режим шейдера с параметром шаблона или отдельные квады, на выбор плана, без аллокаций на кадр.
* Зачёркивание — на середине высоты строчных букв (x-height из метрик шрифта, округлённо).
* CONCEAL и HOST_HIDDEN не рисуют ни глиф, ни оформление (фон остаётся).
* Ссылка под Ctrl+наведением: одинарное подчёркивание всего диапазона ссылки (5.5/5.6) поверх оформления клеток.
* Тест `terminal_renderer_matches_rriter_by_not_emitting_an_underline_layer` заменяется тестами слоя (решение 14).

### 6.3 Ссылки, буфер обмена, cwd

* Ctrl+наведение на ссылку или URL меняет курсор на pointer и подсвечивает диапазон; Ctrl+клик открывает и не передаётся приложению (даже при включённом mouse tracking). Без Ctrl поведение мыши не меняется.
* Открытие: новый хелпер в `src/platform` запускает `xdg-open <uri>` (через `resolve_executable`, без shell-строки) в именованном фоновом потоке, который ждёт завершения процесса (без зомби); путь ввода не блокируется (`AGENTS.md:108`). Разрешённые схемы: `http`, `https`; `file` — только с пустым хостом, `localhost` или локальным именем машины. Остальные — игнорируются. Решение владельца по Q1 (23.10, вариант O2): `xdg-open` получает путь `file://` только если это каталог или обычный файл без бита исполнения (любого из `u/g/o`) и с расширением не `.desktop`; проверка — по пути после разрешения симлинков (`canonicalize`). Исполняемый файл, `.desktop` или симлинк на них — открывается содержащий каталог (тоже через `xdg-open`), сам файл — нет. Несуществующий путь — игнор, одна запись в лог. Причина: ссылку печатает программа, текст OSC 8 может не совпадать с URI, и Ctrl+клик не должен запускать файл. Ошибка запуска — одна запись в лог, без повторов.
* OSC 52 → `set_clipboard_text` в главном потоке.
* OSC 7 (Q12 (а)): новая вкладка стартует в папке OSC 7 активной вкладки, если событие принято (5.8) и папка существует; иначе в `$HOME`, как сейчас. `current_dir` не используется (тест `terminal_process.rs:1395-1403` остаётся).

### 6.4 Ввод

* `input.rs:427` пропускает Release и Repeat в кодировщик; что из них отправить, решает `encode_key` (5.3), без флага 2 результат прежний.
* Хост строит `KeyEvent` (5.3): `Char` — keysym уровня 0 клавиши в активной группе xkb (`xkb_keymap_key_get_syms_by_level`, не текущее состояние с модификаторами); `base` — из `KeyCode` по таблице US (как нынешняя legacy-таблица Ctrl, `input.rs:1199-1226`); `text` — нынешний `text_for_key` с модификаторами; клавиши-модификаторы — из своих keycode.
* Текст клавиши больше не уходит отдельным событием `Text` мимо кодировщика: хост кладёт его в `KeyEvent.text` и отправляет путём текста только при `KeyOutcome::Text`. Так Alt+a при флаге 1 даёт `CSI 97;3u` без лишнего `ESC a`. Подавление текста при Ctrl/Super (`wayland_input.rs:406`) сохраняется для пути текста.
* Ctrl+C (`input.rs:462-464`) — через `encode_key`; копирование при выделении, вставка Ctrl+V (`input.rs:434`) и глобальные сочетания перехватываются до кодировщика, как сейчас.

В модель цвета терминала он не переводится — это не терминал.
* Своя `TermGrid`/`Cell` (`src/app/terminal.rs`) удаляется; потребители (21 файл, раздел 3) переходят на типы крейта. `Cell` крейта не `Copy` (`Arc` в `CellExtra`): копии — `clone()`, литерал в `automation_terminal_ops.rs:139` — конструктор крейта. Процесс и сессия (`terminal_process.rs`), UI вкладок остаются своими; выделение, скроллбэк и reflow живут в сетке крейта и ведут себя как в Ronsole (при смене ширины выделение сбрасывается, строки переносятся заново; положение `scroll_y` после reflow — как в Ronsole: прилипание к низу сохраняется).

* Ввод — новая маршрутизация, а не замена кодировщика (сейчас в PTY уходит только колесо, раздел 3). Правила — как в Ronsole, кодирование — функциями крейта:
  * мышь в теле терминала: при включённом отслеживании нажатия, отпускания, движение (по режиму 1000/1002/1003) и колесо уходят приложению в кодировании по режиму (1006 или legacy) с реальными колонкой и строкой; обход отслеживания для локального выделения (модификатор) и колесо без отслеживания колесо в альтернативном экране — как в Ronsole; жёстко заданная `\x1b[<{button};1;1M` (`wheel.rs:572-584`) и проверки bool `mouse_tracking` (`mouse_editor_terminal_press.rs:154`, `mouse_drag_capture.rs:143`) заменяются режимом сетки;

  * вставка в терминал: обёртка bracketed paste при 2004;
  * клавиши: winit → `KeyEvent` (5.3): `Char` — `key_without_modifiers()` (winit `KeyEventExtModifierSupplement`), `base` — из `PhysicalKey::Code` по таблице US, `text` — нынешний `logical_text`; Ctrl+C (`keyboard.rs:589`) — через `encode_key`, коммит IME (`keyboard.rs:533`) — путь текста (5.3). Свой `terminal_key_sequence` удаляется.
* Рендер `src/render_view/terminal_ui.rs`: фон любого цвета (сейчас рисуются только индексы < 16), truecolor, inverse, dim, начертания, слой оформления — по правилам 6.1–6.2 и пиксельной стабильности RRiter (`AGENTS.md` §5 Render Hot Paths). Фон по умолчанию не рисуется (решение 20): клетка рисует фон, только если после inverse её фон не равен фону по умолчанию; явные фоны — с той прозрачностью, что сейчас у индексных. Шрифты Bold/Italic/BoldItalic встраиваются в `src/fonts/` RRiter и используются только терминалом (Q11).
* Ссылки: Ctrl+наведение/клик в теле терминала — как 6.3, открытие через `platform::open_url`. OSC 52 → `App::set_clipboard_text`. ## 10. Приёмка

1. Все пункты раздела 8 зелёные; `make codex_test` зелёный в Ronsole и в RRiter.
2. RRiter собирается с git-ревизией крейта (не `path`); `cargo check` крейта под Windows- и macOS-таргетами проходит.

4. Нет регрессии памяти Ronsole в простое: RSS после старта и `smaps_rollup` не выше нынешнего более чем на 1 MiB без использования новых начертаний (замер до/после).

6. Ни одна последовательность не замораживает экран дольше 150 мс: `printf '\e[?2026h'` без `l` — через 150 мс вывод виден (вручную в обоих терминалах).
