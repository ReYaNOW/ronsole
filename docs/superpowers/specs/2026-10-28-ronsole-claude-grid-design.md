# Ronsole: сетка Claude — спека

Дата: 28.10.2026. Kanri: `xmuahrfm` (сетка), `zrofnj42` (сплиты — следующая ветка, переиспользует ядро из этой спеки, §4.1 «Сплиты»).

## 1. Цель

Пользователь держит несколько сессий Claude Code по одной на вкладку и прыгает между ними. По хоткею все вкладки, где на переднем плане Claude Code, показываются плиткой в одном окне. Плитки — живые терминалы своего размера: в них видно вывод, вопросы и диалоги разрешений Claude, в плитку в фокусе можно печатать. Повторное нажатие возвращает обычный вид. Вкладки не перестраиваются.

Успех: при 2–6 сессиях Claude пользователь видит их одновременно, печатает в любую кликом в плитку, выходит в обычный вид на нужную вкладку; вне сетки поведение Ronsole не меняется; в простое сетка не рисует кадры.

## 2. Принятые решения

| # | Вопрос | Решение |

| Q1 | Показывать ли над плиткой состояние Claude (работает / ждёт ответа / закончил) | Нет, в первой версии только имя (§4.3). Плитки живые, диалог разрешения виден на самой плитке; эвристика по экрану хрупкая. Если понадобится — отдельной задачей на хуках Claude Code |
| Q2 | Хоткей и выход из сетки | Ctrl+Shift+S включает и выключает сетку. Enter и Esc уходят в терминал. Плитку разворачивают двойной клик по её заголовку или повторный Ctrl+Shift+S; после выхода активна вкладка плитки в фокусе |
| Q3 | `tab-status` для плиток | Каждая видимая плитка отвечает `active=1`; формат ответа не меняется |
| Q4 | Больше 6 вкладок с Claude | Сетка без предела по числу, размер по числу плиток (физический предел — Q9) |

| Q6 | Полоса вкладок в сетке | Остаётся видна; клик по вкладке выходит из сетки на неё |

Отвергнуты: отдельный рендер сетки (вторая реализация тела) и offscreen-текстуры на терминал (скрытые FBO, VRAM — запрет AGENTS §5) |

## 3. Факты кода, на которые опирается спека

- Тело терминала рисует `Renderer::render_terminal_app` (`src/renderer/terminal_ui.rs:3395`) только для `terminals[active_terminal]` через `render_terminal_body` (`:3468`). Прямоугольник тела — `terminal_body_rect(width, height, scale)` (`:190`), из размера окна. Очистка кадра — внутри тела (`:3479-3480`). Акцентный разделитель сверху тела — `:3511`, `:3744-3753`; FPS-оверлей позиционируется по `layout.body` (`:3463`).
- Поиск: тело передаёт окно-глобальный `search` в `prepare_terminal_grid_for_render`, где при `search.shown` вызывается `refresh_for_grid` для рисуемого терминала (`:1400-1413`, `:3492`, `:3501`); подсветка `search.row_matches` и `draw_search_overlay` — в теле (`:3541-3546`, `:3755-3757`).
- Cols/rows считаются при рендере из прямоугольника тела (`:3487-3488`); при смене размера рендер вызывает `terminal.resize_pty` (`:3496`). Неактивная вкладка держит старый размер до своей активации.
- Hit-test мыши (`src/input.rs`) берёт одну раскладку `TerminalInteraction.layout`, её обновляет `src/app.rs:2276` из результата рендера активного терминала. Её же читают automation (`src/app/automation.rs`) и headless-dump (`src/headless/dump.rs:80-82`).
- Активация вкладки: `request_terminal_activation` откладывает её (`src/app.rs:735-742`); `activate_ready_terminal` (`:688-712`) шлёт focus-out/focus-in 1004, вызывает `reset_for_terminal_switch` (`src/input.rs:235-248`: обнуляет `layout`, `pointer_capture`, закрывает поиск) и ставит `active_terminal_presented = true` (`:709`). Флаг означает «отложенная активация завершена», сбрасывается при закрытии вкладки до готовности новой (`:965`, `:988-1013`), управляет 1004 при смене фокуса окна (`:1191`) и проверками automation (`src/app/automation.rs:1046`, `:1267`, `:1434`).
- `close_terminal_tab_at` сам активирует соседа через `active_index_after_remove` (`src/app.rs:1003-1012`, `src/tabs.rs:116-127`).
- Плавная прокрутка обновляется только у активного (`src/app.rs:2224-2232`); `sync_animation_state` смотрит только на активную (`:1616-1620`); колесо — только в активную (`:2190-2192`); `withhold_active_frame` и скрытие баннера dev-channels — только для активной (`:815-841`). `scroll_y` и `hovered_link` — на терминал (`src/terminal.rs:1576`, `:1593`).
- Отметка BEL ставится по условию `index != active` (`src/app.rs:2322-2325`).
- Поток заголовков каждой сессии раз в 250 мс снимает процесс переднего плана (`refresh_terminal_title_cache`, `src/terminal_process.rs:787-843`); снимок `ProcessSnapshot` — exe, cwd и args самого глубокого процесса группы, без `comm` (`src/platform/process.rs:13-18`, `:98-105`); функция выходит рано, если снимок не изменился (`:841-842`). Claude Code определяется по `comm == "claude"`: `claude_generation(pgrp)` (`src/tab_input.rs:98-104`), `claude_process_group_from` (`:109-114`).
- `tab-status`: `active: index == self.active_terminal && self.active_terminal_presented` (`src/app/tab_delivery.rs:115`).
- Глобальные хоткеи — `global_shortcut` (`src/app.rs:136`): F1, Ctrl+F8, Ctrl+Shift+T, Ctrl+4, Ctrl+F. В настройках разрешены только F1 и Ctrl+F8.

- Headless: `bootstrap_headless` на Mesa surfaceless (`src/runtime.rs:2804`; тестовый хелпер `headless_runtime` — `:3779-3788`), команды `key` и `screenshot` (`src/headless/protocol.rs:110`, `:126`); подставной процесс с именем `claude` уже используется в тестах (`src/tab_input.rs:626-632`). Pure-тесты app с несколькими вкладками и проверкой байтов 1004 есть (`src/app.rs:2508-2509`, `:3833`).

## 4. Дизайн

### 4.1. Ядро: панели

Панель — терминал (индекс в `App.terminals`) плюс прямоугольник тела в физических пикселях и признак «плитка» (заголовок, рамка). App пересобирает список панелей из своего состояния перед каждым кадром и перед обработкой событий указателя (scratch-вектор на App, `clear()`, без аллокаций в кадре); между кадрами индексы не хранятся, поэтому удаление и перестановка вкладок не оставляют устаревших записей.

- Обычный режим — одна панель `active_terminal` на всё тело окна (`terminal_body_rect`).
- Сетка — по панели на плитку (§4.3).

**Размер.** Cols/rows из прямоугольника считает отдельный чистый хелпер (вынесен из `render_terminal_body`, те же формулы и snapped-хелперы); рендер вызывает его и при смене размера — `resize_pty` терминала панели.

**Рендер.**
- `render_terminal_app` принимает список панелей; кадр очищается один раз в начале, не в теле.
- Тело рисуется для каждой панели в её прямоугольнике под scissor той же функцией тела с прямоугольником аргументом.
- Тело получает `search: Option<&mut TerminalSearchState>`: `Some` только для панели `active_terminal`. Обновление поиска в `prepare_terminal_grid_for_render`, подсветка совпадений и оверлей поиска выполняются только при `Some`.
- Курсор — только в панели `active_terminal` и только при фокусе окна (как сейчас).
- Акцентный разделитель сверху тела — только в обычном режиме; в сетке акцент — рамка плитки в фокусе (§4.3).
- FPS-оверлей позиционируется от `terminal_body_rect` окна, а не от тела панели.
- Рендер возвращает раскладку (`TerminalUiLayout`) каждой панели. `interaction.layout` — всегда раскладка панели `active_terminal` (её продолжают читать `input.rs`, automation и headless-dump); раскладки остальных панелей — в переиспользуемом векторе App рядом со списком панелей.
- **Поколение состава** (только в режиме сетки; вне сетки обработка указателя не меняется). App держит счётчик, который растёт при смене набора плиток, их порядка, размера окна или scale. Сохранённые раскладки помечены поколением кадра, в котором получены. Нажатие кнопки при несовпадении поколения не делает действия в ячейках: только выбирает плитку (если это другая) и запрашивает кадр; отпускание, парное к такому нажатию, в терминал не передаётся (нет непарного release). Колесо и hover при несовпадении поколения пропускаются. Рост поколения снимает захват указателя.

**Кадры и анимации.** Плавная прокрутка (`scroll_y.update`; clamp по `max_scroll` раскладки своей панели, а не `interaction.layout`) и `sync_animation_state` проверяют все видимые панели, а не только активную.

**Баннер dev-channels.** Вне сетки — без изменений (`withhold_active_frame` удерживает кадр по активной вкладке). В сетке кадр не удерживается: панель, чей терминал сейчас надо скрыть, рисует только фон тела, остальные рисуются как обычно. Перед кадром пересканирование (`observe_dev_channel_warning` и `observe_dev_channel_banner`, сейчас в `withhold_active_frame`) выполняется для каждой видимой панели. Кадр, где хоть одна панель нарисовала только фон, запоминает `withheld_until` — минимум `dev_warning_hidden_until` среди таких панелей (сам кадр показывается). `advance_dev_channel_warnings` в сетке при `now >= withheld_until` сбрасывает его и запрашивает кадр — плитка перерисовывается и без нового вывода; следующий кадр, если скрытые панели ещё есть, ставит новое значение, иначе цикл уходит в простой. Дедлайн цикла (`dev_warning_hidden_until` в расчёте `AppLoopControl`) в сетке — `withheld_until`, а не дедлайн активной. Условие «хоть одна истекла» по `dev_warning_hidden_until` не годится: он возвращает `Some` и после истечения, пока виден текст предупреждения. Комментарии к `frame_withheld` и `advance_dev_channel_warnings` («skipped frame») обновляются под оба режима.

**Ввод.**
- Клавиатура, текст, IME, вставка с клавиатуры, поиск — `active_terminal`, без изменений.
- Мышь: панель выбирается по точке (`rect.contains`). Колесо прокручивает панель под указателем без смены фокуса: `mouse_wheel` получает терминал и раскладку панели аргументом (включая мышиные протоколы и alternate screen — как сейчас для активной), `interaction.layout` не подменяется.
- Hover ссылок — только в панели под указателем; при уходе указателя в другую панель или за пределы панелей hover прежней панели снимается.
- Нажатие любой кнопки в панели, которая не `active_terminal`: `cancel_terminal_presentation_intents()`, затем `activate_ready_terminal(i, false)` (плитка уже показана, отложенная активация не нужна; focus-out/focus-in 1004 как сейчас; `reset_for_terminal_switch` закрывает поиск — это ожидаемо), затем `interaction.layout` заполняется раскладкой панели `i` из вектора панелей, затем нажатие обрабатывается существующим `mouse_input` (средняя кнопка вставляет в эту плитку).
- Захват указателя остаётся у панели, где нажали, до отпускания; координаты не зажимаются (выход за край нужен автопрокрутке выделения, `update_selection_autoscroll`, `src/input.rs:296`). Если панель захвата исчезла (вкладка закрыта, Claude завершился, выход из сетки), захват снимается так же, как сейчас при переключении вкладки.

**Видимость.** Флаг `active_terminal_presented` остаётся с прежним смыслом. Добавляется `tab_visible(i)`, вычисляемая из состояния App (не из отрисованного кадра): в сетке — `i` среди плиток; иначе — `i == active_terminal && active_terminal_presented`. `tab-status` использует `tab_visible`. Отметка BEL: в сетке видимые плитки её не получают; вне сетки — по-прежнему `index != active_terminal`. Focus reporting 1004 и automation продолжают опираться на `active_terminal` и флаг.

**Сплиты.** Следующая ветка переиспользует: рендер тела в прямоугольник, хелпер размера, список панелей, выбор панели по точке, захват, анимации и `tab_visible` по видимым панелям. Изменится адресация: сейчас вкладка = один терминал, и панель адресует индекс в `App.terminals`; со сплитами вкладка станет контейнером нескольких сессий, и панель будет адресовать сессию стабильным id. Эта ветка не вводит модель сессий внутри вкладки.

### 4.2. Признак «вкладка с Claude»

Поток заголовков сессии на каждом тике (250 мс), независимо от ранних выходов `refresh_terminal_title_cache`, вычисляет флаг «лидер группы переднего плана — Claude Code»: `claude_generation(process_group).is_some()` (тот же критерий `comm == "claude"`, два чтения `/proc`, без обхода; дочерние инструменты Claude остаются в его группе, поэтому флаг от них не мигает). Флаг хранится в `TerminalTitleCache`; цикл будится только при смене флага. Если группы переднего плана нет — флаг снят. Новых таймеров и обходов `/proc` нет; AGENTS §7 соблюдён.

Состав сетки — вкладки с флагом в порядке вкладок. Флаг появился — плитка появляется в открытой сетке без действий пользователя; пропал (Claude завершился, вкладка закрыта) — плитка пропадает.

### 4.3. Режим сетки

- **Вход:** Ctrl+Shift+S (точные модификаторы, как у остальных глобальных). Не действует при открытых настройках и диалоге закрытия (существующие гейты `on_key`). Нет вкладок с Claude — сетка не включается, на полосе вкладок ~2 с подсказка «Нет вкладок с Claude» (реальный дедлайн цикла, без опроса; текст константный). Плитки не помещаются — Q9.
- **Фокус при входе:** отложенные намерения активации отменяются (`cancel_terminal_presentation_intents()`); фокус — активная вкладка, если она с Claude, иначе первая плитка (активируется как при клике).
- **Раскладка:** `cols = ceil(sqrt(n))`, `rows = ceil(n / cols)`; плитки заполняют тело окна под полосой вкладок по рядам, слева направо, в порядке вкладок; последний неполный ряд — плитки той же ширины, выровненные влево. n = 1 — одна плитка на всё тело. Границы плиток — snapped к целым пикселям одним хелпером (AGENTS §4); промежуток между плитками и высота заголовка — константы в логических пикселях × scale. Минимальное тело плитки — 10 колонок × 2 ряда; порог Q9 считается по сырому расчёту хелпера размера до зажимов `.max(10.0)` / `.max(2.0)`.
- **Заголовок плитки:** одна строка с отображаемым заголовком вкладки (он уже начинается с имени каталога проекта), обрезанным с многоточием по ширине; текст и обрезка кэшируются при смене заголовка или ширины, не форматируются в кадре. Плитка `active_terminal` — с рамкой акцентного цвета.
- **Выход из сетки** (обычный вид, активна указанная вкладка). Выход привязан к путям:
  - повторный Ctrl+Shift+S — вкладка плитки в фокусе;
  - двойной клик по заголовку плитки — её вкладка;
  - клик по вкладке на полосе (`select_terminal_tab_from_user`; так же переключает вкладки automation) — эта вкладка;
  - `add_terminal_with_launch` (Ctrl+Shift+T, внешний запуск через single instance) — в момент запроса, новая вкладка;
  - пропала последняя плитка — текущая `active_terminal`;
  - Q9 при открытой сетке — вкладка плитки в фокусе.
- **Перенос фокуса без выхода:** закрытие вкладки или пропажа флага у плитки в фокусе при оставшихся плитках — фокус на следующую плитку по порядку, иначе на предыдущую (`cancel_terminal_presentation_intents()`, затем `activate_ready_terminal`, как при клике); сетка открыта. В режиме сетки при закрытии вкладки в фокусе (`index == old_active`) `close_terminal_tab_at` берёт цель из плиток вместо `active_index_after_remove` и не ставит отложенную активацию соседа без Claude; закрытие другой вкладки только сдвигает индекс, как сейчас; плиток не осталось — обычный путь закрытия и выход из сетки.
- **Поиск** (Ctrl+F) — по плитке в фокусе, оверлей поиска в её прямоугольнике. Клик в другую плитку закрывает поиск.
- Настройки и диалог закрытия — модально поверх всего окна, как сейчас. FPS-оверлей — поверх окна (§4.1). Полоса вкладок рисуется как сейчас.
- Режим не сохраняется между запусками.

PTY меняет размер при каждом входе (все плитки получают размер плитки) и выходе (активная вкладка — размер тела окна). Вкладки, которые были плитками и не стали активными после выхода, держат размер плитки до своей активации (существующая ленивая подгонка). Claude Code перерисовывается под новый размер.

### 4.4. Harness (`tab-status`, `TAB_INPUT`)

`tab-status` отвечает `active = tab_visible(i)` (§4.1): в сетке — каждой плитке, вне сетки — как сейчас. `focused` — фокус окна, как сейчас. Формат 3-байтного ответа и версия протокола не меняются. `TAB_INPUT` адресует вкладку по токену и от видимости не зависит — без изменений.

## 5. Ограничения (AGENTS.md)

- В кадре: без файлового ввода-вывода, `/proc`, `format!` и растущих аллокаций; списки панелей и раскладок — на долгоживущем состоянии, `clear()`.
- Рендер только при dirty; сетка в простое не рисует. Вывод любой плитки перерисовывает кадр целиком (dirty-трекинга по плиткам нет — как сейчас для одного тела).
- Поиск пересканирует только сетку `active_terminal` (правило `src/search.rs`, AGENTS §7).
- Геометрия плиток и тел — через существующие snapped-хелперы; одинаковая геометрия для текста, курсора, выделения и hitbox.
- Одна реализация тела и hit-test для обычного режима и сетки.
- Терминальное поведение крейта `ronsole-term` не меняется.
- Тесты на структуру исходника, привязанные к нынешнему тексту рендера и ввода (`src/app.rs:2864-2937`, `:4655-4686`, `src/runtime.rs:3762-3776`), обновляются в той же правке, что меняет этот текст.

## 6. Тесты

Pure (без GL):
- хелпер размера: cols/rows из прямоугольника совпадают с нынешним расчётом тела для окна; для плиток — по их прямоугольнику при scale 1, 1.5, 2;
- раскладка сетки для n = 1…9 при scale 1, 1.5, 2: плитки не пересекаются, лежат в теле окна, границы целые, порядок по вкладкам; порог Q9;
- выбор панели по точке, включая промежутки и заголовок;
- вход и все пути выхода §4.3, фокус при входе, перенос фокуса при закрытии вкладки и пропаже флага без выхода, выход при пропаже последней плитки, Q9 на входе и при открытой сетке;
- 0 вкладок с Claude: сетка не включается, подсказка с дедлайном;
- клик в неактивную плитку: смена `active_terminal`, байты focus-out/focus-in 1004, `interaction.layout` = раскладка этой плитки, сетка открыта; колесо над неактивной плиткой прокручивает её и не меняет фокус;
- `tab_visible` и `tab-status`: `active=1` для всех плиток, вне сетки — как сейчас; BEL не отмечает видимые плитки;
- анимация прокрутки неактивной плитки получает кадры (`animation_active`);
- поиск в сетке не обновляется для неактивных плиток;
- флаг Claude: вычисляется на тике без изменения снимка, будит только на смене (подставной процесс `claude`, ограниченное ожидание тика);
- поколение состава: нажатие после смены состава до нового кадра не делает действия в ячейках и не попадает в геометрию другой плитки, парное отпускание не уходит в терминал, колесо и hover пропускаются; рост поколения снимает захват; вне сетки поколение не проверяется;
- Q9 при смене размера шрифта в открытой сетке;
- отложенное намерение активации, висящее при входе в сетку или клике по плитке, отменяется и позже фокус не перехватывает;
- закрытие вкладки в сетке: фокус на соседнюю плитку, не на вкладку без Claude, лишних 1004 нет;
- баннер dev-channels в сетке: скрываемая плитка рисует только фон, остальные рисуются, кадр не удерживается, после истечения скрытия плитка перерисована без нового вывода (дедлайн по неактивной плитке будит цикл), затем цикл уходит в простой; две скрытые плитки с разными дедлайнами — первая перерисована в свой дедлайн;
- BEL вне сетки — как сейчас (`index != active_terminal`).

Headless (обязательно): снимок окна с сеткой из 4 плиток с подставными процессами `claude` — ключ `key` с Ctrl+Shift+S, ограниченное ожидание тика 250 мс, `screenshot`; снимок сохраняется в `/tmp` для пользователя.

## 7. Риски

- Каждый вход и выход меняет размер PTY плиток; Claude Code перерисовывается, вероятно с кратким мерцанием (не проверено).
- N тел в кадре — N× ячеек и draw-вызовов; память вершин не растёт (общий буфер с flush). Измерение — FPS-оверлей при 6 плитках под потоком вывода.
- На маленьких плитках колонок мало; при многих плитках на обычном мониторе текст Claude переносится сильно — пользователь принял сетку без предела по числу (Q4), физический предел — Q9.
