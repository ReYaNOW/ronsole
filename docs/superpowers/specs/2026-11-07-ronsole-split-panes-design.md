# Ronsole: сплиты панелей внутри вкладки — дизайн

Карточка Kanri: `zrofnj42` («Ronsole: сплиты панелей внутри вкладки»).
Дата: 2026-11-07.

## 1. Цель

Вкладку терминала можно делить на панели по горизонтали и вертикали, с вложенностью (слева одна, справа две друг над другом). В каждой панели свой shell и свой процесс; остальные вкладки не меняются. Активная панель выделена рамкой, переключение кликом и `Alt+стрелки`, ввод идёт в активную панель, границу тянут мышью. Закрытие панели отдаёт её место соседней, закрытие последней панели закрывает вкладку.

Причина: пользователь держит несколько Claude Code в одном проекте и переключается между ними; сплиты позволяют видеть две-три сессии рядом вместо одной вкладки на сессию. Сетка Claude (`xmuahrfm`, уже сделана) решает временный просмотр всех сессий, сплиты — постоянную раскладку.

## 2. Не входит в задачу

* Сохранение раскладки, состава вкладок и рабочих каталогов между запусками (Q1). Сейчас между запусками даже вкладки не сохраняются (`src/config.rs` хранит только размер окна, шрифт, палитру и прочие настройки). «Восстановление сессии» — отдельная карточка.
* Перенос панели в другую вкладку, Drag&Drop панелей.
* Разворот панели на всю вкладку (zoom) и «уравнять размеры».
* Смена формы указателя над границей: Ronsole сейчас не устанавливает курсоры Wayland, добавление — отдельная задача.

## 3. Принятые решения

| # | Вопрос | Решение |
|---|--------|---------|
| Q1 | Сохранять раскладку между запусками? | Нет. Как вкладки: сессия начинается с одной вкладки. Восстановление сессии — отдельная карточка. |
| Q2 | Хоткеи фокуса | `Alt+←/→/↑/↓`. Перехватываются, только когда в активной вкладке две и более панелей; в одиночной вкладке Alt+стрелки уходят в приложение, как сейчас. Цена: в раскладке приложение не получает Alt+←/→; в bash переход по словам остаётся на `Ctrl+←/→` (`\e[1;5D`/`\e[1;5C`, проверено на машине; `\e[1;3D`/`\e[1;3C` — Alt). fish и zsh эти последовательности по умолчанию не биндят. |
| Q2a | Хоткеи создания и закрытия | `Ctrl+Shift+D` — разделить активную панель по вертикали (новая справа); `Ctrl+Shift+E` — по горизонтали (новая снизу); `Ctrl+Shift+W` — закрыть активную панель, перехватывается только когда в вкладке ≥2 панелей; закрытие вкладки в одиночной панели — `Ctrl+4`, как сейчас (§7). |
| Q3 | Сетка Claude при сплитах | Плитка — панель, а не вкладка: в члены сетки попадают панели с `claude_foreground`, независимо от того, единственная ли панель в вкладке. Выход из сетки возвращает раскладку как была. |
| Q4 | Путь работы | Architectural: спека → консультант и `ds-high` → план → SDD. |
| T1 | Минимальный размер панели | Те же пороги, что у сетки: `raw_cols >= 10` и `raw_rows >= 2` от `terminal_grid_size` (`src/renderer/terminal_ui.rs:1438`). Сплит, который их нарушит, не создаётся и показывает подсказку. Сохранённый `ratio` от размера окна не зависит: панели сжимаются по нему, а к минимуму клампятся только при отрисовке (§5). |
| T2 | Зазор и рамка | Зазор между панелями 6 логических px (как `GRID_TILE_GAP`), рамка активной панели — акцентный прямоугольник 2 px по краю тела, тот же цвет, что у сепаратора фокуса (`terminal_focus_separator_rect`, `src/renderer/terminal_ui.rs:242`). |
| T3 | Новая панель | Тот же shell (`resolve_terminal_shell`), рабочий каталог — из OSC 7 активной панели, если каталог существует (как новая вкладка, `add_terminal`, `src/app.rs:836`). |
| T4 | Пропорции при сплите | По умолчанию 0.5; ресайз мышью меняет пропорцию узла, минимумы T1 соблюдаются. |

## 4. Модель данных

Сейчас вкладка = `Terminal`, все они лежат в `App.terminals: Vec<Terminal>`, активная — `App.active_terminal: usize` (`src/app.rs:532`). Панели уже адресуются индексом в `terminals`: `Panel { terminal: usize, body: Rect, header: Option<Rect>, content_hidden: bool }` (`src/panels.rs:17`). Это позволяет оставить `terminals` плоским хранилищем и добавить группировку вкладок с деревом раскладки поверх.

Новые сущности (новый модуль `src/split.rs`, чистые типы и геометрия):

```rust
pub(crate) enum SplitAxis { SideBySide, Stacked }   // SideBySide = вертикальная граница, Stacked = горизонтальная

pub(crate) enum SplitNode {
    Leaf(PaneId),
    Split {
        axis: SplitAxis,
        /// Доля первой ветви, 0.0 < ratio < 1.0.
        ratio: f32,
        first: Box<SplitNode>,
        second: Box<SplitNode>,
    },
}

pub(crate) struct PaneId(u64);      // стабильный id панели, выдаётся при спавне
```

* `Terminal` получает поле `pane_id: PaneId`; `PaneId` выдаёт `App` монотонным счётчиком, переиспользование после закрытия запрещено.
* Новая структура вкладки в `src/app.rs`:

```rust
struct Tab {
    id: TabId,
    layout: SplitNode,   // всегда с хотя бы одним Leaf
    active_pane: PaneId,
    title_number: usize, // номер в заголовке вкладки, выдаётся при создании вкладки
}
```

`App.tabs: Vec<Tab>` задаёт порядок вкладок (заменяет неявный порядок `terminals`). `App.active_tab: usize`; `App.active_terminal: usize` остаётся индексом в `terminals` и совпадает с `active_pane` активной вкладки. Индекс панели по `PaneId` ищется маленьким проходом `terminals.iter().position(...)`.

Числа: дерево и `terminals` синхронны всегда — инвариант «каждый Leaf ссылается на существующий `Terminal`, каждый `Terminal` принадлежит ровно одной вкладке» проверяется в отладочных `debug_assert` и тестах.

**Единая операция активации.** Все переходы фокуса идут через `App::activate_pane(PaneId, reveal_tail: bool)`: она находит вкладку-владельца, выставляет `active_tab`, `Tab.active_pane` и `active_terminal`, сбрасывает `interaction` при смене терминала и шлёт фокус-репорт 1004 через существующий `send_terminal_focus_state` — тот же набор действий, что сейчас делает `activate_ready_terminal` (`src/app.rs:775`). Семантика существующей функции сохраняется целиком: `active_terminal_presented`, `pending_tab_reveal`, сброс bell и передача focus 1004 (`src/app.rs:775-798`). Параметр `reveal_tail` — та же политика раскрытия хвоста, что у `activate_ready_terminal`. Клик по панели, `Alt+навигация` и новая панель сплита передают `false`; отложенная активация и новая вкладка — те значения, что передают их текущие вызовы (`src/app.rs:817`).
Через `activate_pane` идут клик по панели, `Alt+стрелки`, отложенная активация (`activate_ready_terminal`), выбор плитки сетки (`select_grid_tile`) и выбор преемника после закрытия.

Отдельная операция для фоновой вкладки: `select_tab_pane_in_background(TabId, PaneId)` обновляет только `Tab.active_pane` этой вкладки — без смены `active_tab`, `active_terminal`, `interaction` и без focus reporting. Она нужна, когда закрывается или сама завершается панель неактивной вкладки (§6.4).

Прямых присваиваний `active_terminal` и `Tab.active_pane` вне этих двух операций нет, кроме индексной поправки при удалении панели (ниже).

**Индексная поправка.** `active_terminal` — индекс в `Vec<Terminal>`, поэтому удаление элемента левее активного уменьшает его на единицу без смены логического фокуса и без focus reporting. Это делает общий шаг удаления панели, а не операция активации. Логическая идентичность фокуса — `PaneId`: после поправки `terminals[active_terminal].pane_id` обязан совпадать с активным `PaneId` (проверка `debug_assert`).

**Инвариант `Tab.active_pane` и преемник.** `Tab.active_pane` сохранённой вкладки всегда указывает на существующую панель этой вкладки. Преемник при удалении панели — ближайший предшествующий лист в порядке обхода дерева, если его нет — следующий; правило общее для активной и фоновой вкладки и не зависит от геометрии, видимости и открытой сетки.
У активной вкладки совпадение `Tab.active_pane` с `active_terminal` и focus reporting восстанавливает `activate_pane` (§6.4); у фоновой — `select_tab_pane_in_background`.
Пакетное закрытие (`close_tab`): внутренний шаг удаления сразу переводит `Tab.active_pane` на преемника по дереву, не вызывая `select_tab_pane_in_background` и не отправляя focus reporting; глобальный фокус шлёт один `activate_pane` в конце. Отказ cleanup восстанавливает прежний глобальный фокус тем же `activate_pane`, при этом дерево и `Tab.active_pane` уже соответствуют оставшимся панелям.

## 5. Геометрия раскладки

Чистая функция в `src/split.rs`, по образцу `grid_tiles` (`src/panels.rs:32`):

```rust
pub(crate) fn layout_panes(
    root: &SplitNode,
    body: Rect,
    scale: f32,
    char_w: f32,
    char_h: f32,
    out: &mut Vec<(PaneId, Rect)>,
)
```

* Зазор между ветвями — `(GAP * scale).round()`, целое число пикселей, как `GRID_TILE_GAP` в `src/panels.rs:70`; дробного зазора (6 × 1.25) в раскладке нет.
* Обход дерева: узел `Split` делит свой `Rect` по оси на две части с этим зазором; размер первой ветви — `floor` от доступного пространства по `ratio`, второй — остаток, поэтому обе половины целые и вместе с зазором точно покрывают родителя.
* `Leaf` кладёт `(PaneId, Rect)`.
* Функция без аллокаций внутри: `out` заполняется через `clear()` и переиспользуется в `App` (как `grid_tile_rects`).
* Минимум листа в пикселях: `pane_min(char_w, char_h, scale) -> (f32, f32)` = `(10 * char_w + 20 * scale, 2 * char_h + 16 * scale)` — ровно те значения, при которых `terminal_grid_size` даёт `raw_cols >= 10` и `raw_rows >= 2`.
* Минимум поддерева считается рекурсивно и зависит от оси разреза: для `SideBySide` ширина = `min_first.w + gap + min_second.w`, высота = `max(min_first.h, min_second.h)`; для `Stacked` наоборот — высота сумма с зазором, ширина максимум. Минимум листа — `pane_min`.
* Перед сравнением с пикселями минимумы округляются вверх (`ceil`), чтобы `floor` доли первой ветви не оказался ниже минимума.
* Хранится только желаемый `ratio`. При отрисовке узел сжимает его до диапазона `[min_first / available, 1 - min_second / available]` по своей оси; в дереве `ratio` при этом не меняется, поэтому после уменьшения и восстановления окна раскладка возвращается к прежним пропорциям.
* Доступное пространство по оси узла — `available = max(parent_extent - gap, 0)`: зазор вычитается один раз, и сравнение с минимумами идёт уже от `available`. Если сам `parent_extent < gap`, зазор становится `0` и `available = parent_extent`.
* Если `available < ceil(min_first) + ceil(min_second)` (окно сильно уменьшили), пространство делится по сохранённым пропорциям без клампа, оба `Rect` неотрицательны, а панель рендерится с минимальной сеткой 10×2 (`terminal_grid_size` уже клампит). Содержимое панели обрезается по её `body`.
* Изменение размера окна не трогает `ratio`: пересчёт идёт от нового `body`.

## 6. Операции

### 6.1 Создание сплита

`Ctrl+Shift+D` (`SideBySide`, новая справа) и `Ctrl+Shift+E` (`Stacked`, новая снизу):

1. Активная панель — `Leaf(id)` в дереве активной вкладки; узел заменяется на `Split { axis, ratio: 0.5, first: Leaf(id), second: Leaf(new) }`.
2. Проверка T1 на будущих прямоугольниках; не проходит — создание отменяется, а в строку вкладок пишется подсказка на пару секунд — тем же механизмом, что подсказки сетки (`grid_hint`, `src/app.rs:2252`).
3. Новая панель спавнится `spawn_terminal_tab`-путём с каталогом из OSC 7 активной панели (T3) и стартовым размером `DEFAULT_SPAWN_GRID`; первый кадр её ресайзит (как у плитки сетки).
4. `Terminal::pane_id` выдаётся при спавне; фокус переводится через `activate_pane(new, false)` (§4), прямых присваиваний `active_pane` и `active_terminal` нет.

### 6.2 Фокус

* `Alt+стрелки` в активной вкладке с ≥2 панелями: направление определяется по геометрии. Кандидаты — панели, чей `Rect` лежит за соответствующей гранью активной. Приоритет: сначала те, у кого перпендикулярный интервал перекрывается с активной панелью (для `Alt+↑/↓` — пересечение по x, для `Alt+←/→` — по y); среди них ближайшая по расстоянию вдоль оси; ничья — большее пересечение, затем меньший `pane_id`. Если пересечения нет ни у кого — ближайшая панель в направлении по расстоянию между центрами. Нет кандидата — фокус не меняется. В сетке Claude (`claude_grid.is_some()`) `Alt+стрелки` не перехватываются и уходят в терминал активной плитки, как сейчас.
* Клик мышью по телу панели фокусирует её (как клик по плитке сетки, `route_grid_pointer_button`, `src/app.rs:2718`), затем нажатие обрабатывается этой панелью.
* Смена вкладки (клик по вкладке, drag, `Ctrl+Shift+T`) делает активной панелью `tab.active_pane`.
* При вкладке с одной панелью `Alt+стрелки` не перехватываются (уходят в приложение).

### 6.3 Перетаскивание границы

* Нажатие в пределах 3 логических px от любой внутренней границы (то есть в зазор между телами панелей) начинает перетаскивание этой границы; фокус при этом не меняется.
* Состояние: `divider_drag: Option<DividerDrag { tab_id: TabId, path: Vec<u8>, axis: SplitAxis, generation: u64, ratio_at_start: f32 }>`; `path` — адрес узла от корня вкладки, `generation` — `structure_generation` (§8.1).
* Нажатие на устаревшей геометрии (поколение не совпало с текущим кадром) не начинает drag, а только подавляет парный release — тот же контракт, что у `route_grid_pointer_button` (`src/app.rs:2736`).
* Движение мыши пересчитывает `ratio` узла из текущей геометрии `body`, ограничивая новую координату границы минимумами поддеревьев (§5); на границе допустимого диапазона значение зажимается, а не отбрасывается.
* Drag отменяется при смене вкладки, входе в сетку и выходе из неё, создании или закрытии любой панели этой вкладки, закрытии вкладки, смене метрик окна. Отмена всегда сбрасывает состояние drag и подавляет парный release; `ratio` возвращается к `ratio_at_start` до структурной мутации, а если мутация удаляет узел пути, существование узла проверяется до неё и откат пропускается.
* Завершение отпусканием кнопки оставляет записанное движениями значение.
* Курсор не меняется (см. §2); граница при наведении не подсвечивается, только активная панель выделена рамкой.

### 6.4 Закрытие

Закрытие панели и закрытие вкладки — две отдельные операции. Сейчас `close_terminal_tab_at` (`src/app.rs:1116`) делает и то и другое и вызывается из `remove_closed_terminals` (`:2050`) по индексу терминала; после перехода так быть не должно.

* `close_pane(PaneId)` — закрытие одной панели пользователем. Сначала запрашивается очистка процесса тем же путём, что сейчас (`take_process_for_cleanup` → `try_schedule_terminal_cleanup`); отказ (`Err`, backpressure, `src/app.rs:1136-1142`) возвращает процесс в `Terminal` и оставляет дерево, хранилище и фокус нетронутыми. Только после принятой очистки `Leaf` удаляется, родительский `Split` заменяется оставшейся ветвью.
* Фокус после закрытия — одна процедура для `close_pane`, `close_tab` и естественного завершения, с учётом состояния сетки:
  1. Вкладка закрытой панели исчезла (панель была последней):
     a. вкладка была активной: сетка открыта — фокус в следующую плитку в порядке сетки, исключая плитки удалённой вкладки, иначе в предыдущую; плиток не осталось — сетка закрывается, и фокус переходит в `active_pane` следующей вкладки по порядку, если её нет — предыдущей; вкладок не осталось — окно закрывается. Сетка закрыта — фокус сразу в `active_pane` соседней вкладки по тому же порядку.
     b. вкладка была фоновой: глобальный фокус не меняется; её плитки уходят из состава сетки, и если плиток не осталось, сетка закрывается.
  2. Вкладка сохранилась:
     a. сетка открыта: закрытая панель была активной плиткой — фокус в следующую плитку в порядке сетки, иначе в предыдущую; плиток не осталось — сетка закрывается, и дальше действует п. 2б. Панель не была плиткой или была неактивной плиткой — глобальный фокус не меняется, `Tab.active_pane` подчиняется инварианту §4.
     b. сетка закрыта: закрыта активная панель активной вкладки — `activate_pane` выбирает преемника по дереву (§4). Закрыта неактивная панель — глобальный фокус не меняется, `Tab.active_pane` подчиняется инварианту §4. Закрыта активная панель фоновой вкладки — глобальный фокус не меняется, а `Tab.active_pane` обновляет `select_tab_pane_in_background` (§4).
* Последняя панель вкладки не делегирует `close_tab` повторно: внутренняя операция `remove_last_pane_of_tab(TabId)` удаляет `Terminal`, её `Tab` и саму вкладку — без повторного подтверждения и без рекурсии.
* `close_tab(TabId)` — закрытие вкладки пользователем. Подтверждение строится по всем её панелям (занятые процессы — `busy_close_targets`, `src/app.rs:1283`), затем панели удаляются тем же внутренним путём, что в `close_pane`, а фокус выбирается один раз в конце по процедуре ниже, с учётом состояния сетки. Отказ очистки любой панели прекращает закрытие: вкладка остаётся с незакрытыми панелями. Восстановление фокуса при отказе: сетка открыта — фокус остаётся на живой активной плите, из какой бы вкладки она ни была; если она исчезла, преемник — следующая живая плитка в порядке сетки, иначе предыдущая; сетка закрывается, только когда живых плиток не осталось, и тогда фокус идёт на `active_pane` активной вкладки. Сетка закрыта — если закрывалась активная вкладка, фокус на `active_pane` этой вкладки (инвариант §4), иначе не меняется. `close_tab` не вызывает `close_pane`, чтобы не запускать подтверждение второй раз. Открытый диалог закрытия отменяется, как сейчас (`cancel_close_dialog`).
* Естественное завершение процесса (`remove_closed_terminals`) удаляет ровно свою панель по `PaneId`; если это последняя панель вкладки — срабатывает `remove_last_pane_of_tab` без подтверждения, процесс уже завершился. Соседние панели и их процессы не трогаются.
* `Ctrl+4` закрывает вкладку целиком (`close_tab` активной вкладки) — жест не меняется.
* Закрытие последней вкладки закрывает окно, как сейчас.

## 7. Ввод и мышь

* Клавиатура идёт в `terminals[active_terminal]` — маршрут не меняется, меняется только то, какой индекс активен.
* `Alt+стрелки` перехватываются в `global_shortcut` (`src/app.rs:140`) как `GlobalShortcut::FocusPane(direction)`. Условие перехвата проверяется в `App::on_key` (`src/app.rs:2411`): `Alt+стрелки` перехватываются, только когда сетка закрыта и в дереве активной вкладки больше одного листа, иначе уходят в терминал обычным маршрутом. `Ctrl+Shift+D/E` перехватываются при закрытой сетке независимо от числа листьев — они и создают первый сплит; `Ctrl+Shift+W` — по тому же предикату, что `Alt+стрелки`.
* Мышь: `panel_hit` (`src/panels.rs:51`) возвращает панель по точке. Координаты остаются глобальными (координаты окна): `TerminalUiLayout.text_x` уже включает `body.x`, а `terminal_cell_from_grid` (`src/input.rs:1033`) сам проверяет `layout.body.contains(x, y)` и вычитает `text_x`. Панель под указателем получает свой `panel_layouts[index]` и глобальные `pointer_x/pointer_y` без сдвига; ручной пересчёт координат запрещён — он сломает hit-test и mouse reporting правых и нижних панелей.
  * Нажатие: панель под указателем становится активной через `activate_pane` (§4), затем событие идёт в неё. Нажатие в зазоре обрабатывается как перетаскивание границы (§6.3) и фокус не меняет; `panel_hit` в зазоре возвращает `None` и в терминал не уходит ничего, кроме подавленного release.
  * Колесо и движение: в панель под указателем (при захвате указателя — в захватившую), фокус от них не меняется.
  * Если `panel_layouts_generation` не совпадает с текущим поколением раскладки (кадр после изменения дерева ещё не отрисован), нажатие только выбирает панель и подавляет парный release — контракт `route_grid_pointer_button` (`src/app.rs:2736`).
* `content_hidden` у панелей раскладки выставляется в `false` при сборке в `rebuild_panels`; перед рендером он может быть поднят для конкретной панели — §8.4.

## 8. Рендер

### 8.1 Порядок

`rebuild_panels` (`src/app.rs:2128`) — единственное место сборки `panels`:

* сетка открыта — как сейчас, но `grid.members` — индексы панелей с `claude_foreground`;
* сетка закрыта — `layout_panes(&tabs[active_tab].layout, body, metrics.scale, metrics.char_w, metrics.char_h, &mut pane_rects)`, по каждому `(pane_id, rect)` панель `Panel { terminal, body, header: None, content_hidden: false }`. `char_w`/`char_h` берутся из `GridMetrics` (`src/app.rs:483`), как их берёт `terminal_grid_size`.

`render_terminal_app` (`src/renderer/terminal_ui.rs:3578`) обходит `panels` без изменений; ресайз PTY на панель (в `render_terminal_body`) уже работает (`:3751`).

**Поколения раскладки.** `structure_generation` растёт при любом структурном изменении: форма дерева (сплит, закрытие панели), состав и порядок вкладок, активная вкладка, вход в сетку и выход из неё, изменение `grid.members`, метрики окна (`set_grid_metrics`, `src/app.rs:2101`). `layout_generation` растёт при тех же событиях и дополнительно при изменении любого `ratio`. Drag проверяет `structure_generation` (§6.3); `panel_layouts_generation` сравнивается с `layout_generation` так же, как сейчас с `grid_generation`; это закрывает момент «событие пришло до кадра с новой геометрией» не только в сетке.

### 8.2 Рамка активной панели

Новый хелпер `pane_focus_border(body: Rect, scale: f32) -> [Rect; 4]` (или один прямоугольник и толщина) в `src/renderer/terminal_ui.rs` рядом с `terminal_focus_separator_rect`: 2 px внутрь от тела активной панели, цвет акцента. Рисуется только когда в активной вкладке ≥2 панелей; в одиночной вкладке остаётся существующий сепаратор сверху, чтобы не менять привычный вид. У панелей многопанельной вкладки верхний сепаратор не рисуется: `render_terminal_body` сейчас включает его для любого не-плиточного тела (`src/renderer/terminal_ui.rs:3783`), поэтому нужен явный признак «панель в сплите» вместо одного `tile: bool`.

Текст, курсор, выделение и хитбоксы панели продолжают использовать snapped-геометрию своего `body`; базлайны не меняются. Зазор — 6 px, границы целые (T2, §5).

### 8.3 Строка вкладок

* Одна вкладка — одна запись в строке вкладок. `draw_terminal_tabs` (`src/renderer/terminal_ui.rs:2518`) сейчас рисует заголовок на каждый `Terminal`; через `TerminalRenderParams` (`src/runtime.rs:2726`) он получает вместо `terminals`/`active_terminal` представление вкладок: срез `(TabId, title, title_number)` в порядке `App.tabs` и `active_tab`. Заголовок — от активной панели вкладки, номер — `tab.title_number`.
* Hit-test, reveal и drag вкладок (`src/tabs.rs`) считаются по индексам `App.tabs`, а не `terminals`; перенос вкладки переносит все её панели.
* Подсказка о невозможном сплите — тот же механизм, что подсказки сетки (`set_grid_hint`).

### 8.4 Производительность

* `layout_panes` — O(панелей), без аллокаций (переиспользуемый `Vec`), вызывается раз в кадр в `rebuild_panels`; при большом числе панелей (типично ≤6) стоимость ничтожна.
* PTY-ресайз остаётся в рендере панели и происходит только при смене размера сетки (`terminal_dimensions_changed` уже есть).
* В hot path нет `format!`, I/O и новых аллокаций на кадр.
* Прокрутка неактивных панелей обновляется в любом режиме, а не только в сетке: сейчас блок обновления `scroll_y.update` для остальных панелей выполняется под условием открытой сетки (`src/app.rs:2890-2919`), а `sync_animation_state` уже учитывает их анимацию (`:1876`); иначе прокрутка панели после смены фокуса застывает и одновременно держит цикл кадров.
* Предупреждение dev-канала: в многопанельной вкладке скрытие считается попиксельно, как в сетке (`observe_grid_dev_warnings`, `src/app.rs:977`): каждая панель получает свой `content_hidden`, кадр не гасится целиком. Целиком кадр удерживается (`withhold_active_frame`, `:955`) только для одиночной вкладки — прежнее поведение.

## 9. Harness: tab-status, TAB_INPUT, tab-wait

Каждый `Terminal` уже несёт свой `tab_token` и `RONSOLE_TAB_TOKEN` в окружении процесса (`src/terminal.rs:2013`, `src/terminal_process.rs:1475`), а `find_tab_by_token` ищет по `terminals` (`src/app/tab_delivery.rs:288`). Поэтому панель автоматически становится отдельной целью, изменения протокола не нужны.

* `handle_tab_status` (`src/app/tab_delivery.rs:111`): `focused` остаётся фокусом окна; `active` = «панель на экране» по новой `tab_visible(index)`: в сетке — панель в `members`; иначе — вкладка панели активна и представлена (`active_terminal_presented`). Видимая панель без клавиатурного фокуса считается активной, поэтому `cc-notify` (молчит при `focused=1 active=1`) не уведомляет о сессии, которая и так на экране.
* `TAB_INPUT` (`accept_tab_input`, `src/app/tab_delivery.rs:203`) доставляется в панель по токену; проверки (foreground — claude, готовность input-box, rate limit) не меняются. `/clear` попадает в панель своей сессии — это и было целью.
* `tab-wait` использует ту же `tab_visible`, семантика «на экране» расширяется на панели автоматически.
* Внешний запуск (single instance) по-прежнему открывает новую вкладку, не панель.
* В режиме сетки (`claude_grid.is_some()`) `Ctrl+Shift+D/E/W` и `Alt+стрелки` не действуют и уходят в терминал активной плитки, как сейчас: сетка — временный обзор, её состав и раскладка не меняются. Предикаты — §7: для `Alt+стрелок` и `Ctrl+Shift+W` «сетка закрыта и больше одного листа», для `Ctrl+Shift+D/E` — только «сетка закрыта». `Ctrl+Shift+S` и `Ctrl+4` работают как раньше.

## 10. Сетка Claude

`collect_claude_members` (`src/app.rs:2197`) уже собирает индексы `terminals` с `claude_foreground` — после перехода на панели это ровно нужное поведение (Q3): разделённая вкладка может дать две плитки, shell-панели в сетку не попадают. Раскладка плиток не меняется. Преемник после закрытия плитки выбирается только процедурой §6.4 (п. 1–2), без отдельного правила: следующая или предыдущая плитка — лишь часть её ветвей, и при закрытии неактивной плитки фокус по ней сохраняется. `grid_successor_after_removal` (`src/app.rs:2232`) — существующая основа выбора следующей/предыдущей плитки внутри этой процедуры; вне сетки он не применяется. Выход из сетки возвращает активную вкладку с её деревом.

## 12. Тесты и приёмка

* Чистые тесты `src/split.rs` по образцу `panels.rs`: `layout_panes` покрывает тело без пересечений и без дробных пикселей при scale 1.0/1.25/1.5/2.0 и деревьях до 6 листьев; сплит/удаление сохраняют инвариант «дерево ↔ панели»; кламп `ratio` держит минимумы; фокус-навигация по геометрии выбирает ожидаемую панель.
* App-тесты: сплит создаёт панель и меняет `panels`; закрытие панели отдаёт место соседу; закрытие последней закрывает вкладку; `Alt+стрелки` при одной панели уходят в терминал, при двух — меняют фокус; клик по панели фокусирует; сетка показывает панели, а не вкладки; смешанная вкладка (Claude + shell) даёт в сетке одну плитку, а выход возвращает сплит.
* Закрытие и перетаскивание: drag границы меняет `ratio` и размеры PTY обеих панелей (по `panel_layouts` и `Terminal::cols/rows`); естественный выход shell (`exit`) убирает только свою панель и оставляет соседние процессы живыми; отказ cleanup оставляет дерево и процесс нетронутыми; уменьшение и восстановление окна возвращает прежние пропорции.
* Harness на двух панелях одной вкладки: обе отвечают `tab-status active=1` при представленной вкладке; `TAB_INPUT` по токену каждой панели приходит ровно в неё (разные маркеры в выводе), `/clear` — в панель своей сессии; `tab-wait` разрешается при видимости панели и возвращает «нет вкладки» после её закрытия; адресация по токену сохраняется после drag вкладки и закрытия другой вкладки.
* Headless PNG: `--size 2560x1440 --scale 1.333`, assert по `dump` для активной панели, снимки всех раскладок и состояний из §8.
* Headless: `shot` для раскладок 2 и 3 панелей (вертикально, горизонтально, вложенно), пустой и заполненный терминал, наведение/нажатие на границу; PNG открываются как изображение (правило `~/projects/ronsole/CLAUDE.md`, «Приёмка UI»): ничего не съехало, зазор и рамка ровные, соседние панели не перекрыты.
